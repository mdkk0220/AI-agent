# AI-agent: 채용 공고 데이터 기반 취업 준비 프로젝트

개인 취업 준비용 학습 프로젝트: 채용 공고 수집·분류·분석 및 지원 보조 에이전트

의료IT 전공 신입이 IT 업계 진로를 **데이터로 정하고**, 그 위에서 지원 업무를 자동화하는 것을 목표로 합니다.
수집 → 분류 → 분석 → 에이전트 순서로 단계별로 쌓습니다.

> 상태: **0단계(준비)**. 사람인 Open API 승인 대기 중이라 수집은 아직 시작하지 않았습니다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 범위·소스·스키마·운영 설계, 저장소 세팅 | 진행 중 |
| 1 | 공고 일일 자동 수집 (일반 스크립트 + SQLite) | 승인 대기 |
| 2 | 분류 체계 설계 + 정답 세트 직접 라벨링 | 대기 |
| 3 | 분류 자동화: 규칙 vs LLM vs 사람인 기본 분류, 정확도 측정 | 대기 |
| 4 | 업종·직무·기술스택 분석, 내 스킬과의 갭, 진로 후보 도출 | 대기 |
| 5 | LangGraph 취업 에이전트 (실데이터 연결) | 대기 |
| 6 | 포트폴리오 정리 | 대기 |

1~4단계는 LangGraph 없이 일반 스크립트로 만들고, 에이전트는 데이터가 쌓인 뒤 5단계에서 얹습니다.

## 폴더 구조

```
collector/    1단계 수집
classifier/   2~3단계 분류·평가
analysis/     4단계 분석
agent/        5단계 LangGraph 에이전트
docs/         소스 조사, 분류 정의서, 일정, 실행 절차
scripts/      일일 실행 스크립트
tests/
data/         수집 DB·로그·백업 (git 에 올리지 않음)
```

## 설계 원칙

- **원본 보존:** API 응답 원본은 그대로 저장하고, 정리된 테이블은 원본에서 다시 만들 수 있게 둡니다.
- **사람이 먼저, 자동화는 나중:** 분류 기준과 정답 세트는 직접 만들고, 자동 분류는 그 정답 세트로 측정합니다.
- **측정해서 말하기:** 분류 방식별 정확도, 클래스별 정밀도·재현율, 혼동행렬을 기록합니다.
- **한계를 명시:** 소스·기간·본문 유무에 따른 한계를 모든 분석 결과에 함께 적습니다.
- **자동 제출 금지:** 에이전트는 초안까지만 만들고, 제출과 최종 판단은 사람이 합니다.

의사결정과 이유는 [DECISIONS.md](DECISIONS.md), 사람인 API 조사 내용은 [docs/sources.md](docs/sources.md)에 있습니다.

## 데이터 출처와 공개 범위

- 채용 공고 데이터 출처: **사람인 채용정보 API** (이 프로젝트는 사람인과 제휴 관계가 없습니다)
- 수집한 공고 원본, DB, API 키, 개인 프로필은 이 저장소에 올리지 않습니다. 코드와 집계 통계, 문서만 공개합니다.
- 수집은 개인 학습 목적이며, 데이터를 재배포하거나 서비스로 판매하지 않습니다.
