# 일정과 체크리스트

하루 3~4시간 기준입니다. 사람인 승인 날짜를 모르기 때문에 날짜 대신 **D-day(수집 시작일 = D1)** 로 적었습니다. 승인이 나는 날 D1로 시작합니다.

가장 중요한 제약: **마감된 공고는 API로 못 가져오므로**, 수집 시작이 하루 늦어질 때마다 그 기간의 공고를 잃습니다. 수집 코드는 승인 전에 미리 만들어 두고, 승인 당일 바로 돌립니다.

## 0단계: 준비 (승인 전에 하는 것)

- [x] 사람인 Open API 이용신청 (승인 대기)
- [x] 사람인 이용 조건, 호출 한도, 응답 필드 조사 → [sources.md](sources.md)
- [x] GitHub 저장소 `AI-agent` 생성 (Public)
- [x] 폴더 구조, `.gitignore`, `.env.example`
- [x] `DECISIONS.md`, `README.md`
- [ ] 수집 코드 작성 (명세 샘플 기준으로 테스트)
- [ ] 의료 도메인 키워드 사전 초안
- [ ] 사람인 사이트에서 IT 공고 30~50개 직접 읽고 카테고리 감 잡기
- [ ] `profile.yaml` 작성 (실제 스킬, 프로젝트, 자격증)
- [ ] 공공데이터포털·로켓펀치 이용 조건 확인 (대체 소스)
- [ ] 승인 메일 확인

## 승인 직후 (D1)

- [ ] 앱 등록 → access-key를 `.env`에 저장 (채팅·깃허브에 올리지 않기)
- [ ] 응답 구조 확인(명세와 같은지, 본문 필드가 정말 없는지)
- [ ] 첫 수집 실행, DB 확인
- [ ] 하루 1회 자동 실행 등록 + 실패 알림 + 백업

## 1단계: 수집 (D1~D7)

- [ ] 7일 연속 자동 실행, 중복 0건
- [ ] 매일 10분: 수집 로그 확인 (성공/실패, 건수)
- 이상 신호: 0건, 전날 대비 급감, 에러 코드 4

## 2단계: 분류 체계 (수집과 병행, D3~D9)

- [ ] 쌓인 공고 60~100개 읽기, 카테고리 v0 수정 ([taxonomy.md](taxonomy.md))
- [ ] 정의서 v1 (정의 + 경계 사례)
- [ ] 정답 세트 50~100건 라벨링 (모델 예측 안 보고)
- [ ] 일부 재라벨링으로 내 일관성 확인
- [ ] 분석용 스냅샷 날짜 고정 + DB 백업

## 3단계: 분류 자동화 (D10~D13)

- [ ] 규칙 분류기 + 평가 스크립트 (정확도, 클래스별 정밀도·재현율, 혼동행렬)
- [ ] LLM 분류기 (선택지 고정, "판단불가" 허용, 결과 캐시, 비용 로그)
- [ ] 규칙 vs LLM vs 사람인 기본 분류 비교, 오분류 원인 분석
- [ ] 개선(v2) 전후 비교표
- [ ] 전체 공고 분류 실행 (분류체계·모델·프롬프트 버전 기록)

## 4단계: 분석 (D14~D17)

답해야 할 질문

1. 신입 대상 공고는 업종별로 몇 건이고, 의료IT 관련은 그중 몇 %인가?
2. 직무별로 제목·키워드에 가장 많이 나오는 기술 10개는?
3. 내 스킬로 요구 기술이 커버되는 공고는 몇 %이고, 기술 하나를 더 배우면 얼마나 늘어나는가? (본문이 없어 추정치임을 명시)

- [ ] 집계 표와 시각화
- [ ] 진로 후보 2~3개와 근거 문장
- [ ] 한계 정리 (표본 크기, 단일 소스, 진행 중 공고만, 본문 없음)
- [ ] 회고 후 5단계 진행 여부 결정 (`DECISIONS.md` 기록)

## 5~6단계: 에이전트, 포트폴리오 정리

4단계 결과를 보고 범위를 정합니다. 일정이 밀리면 포트폴리오 정리를 줄이지 말고 에이전트 범위를 줄입니다.

## 취업 준비 (프로젝트와 별개, 매일 30분~1시간)

- 코딩테스트 입문: 하루 1문제 정도
- CS 기초: 자료구조, DB, 네트워크 중 약한 곳부터
- 마감이 가까운 공고에 지원하고 싶으면 이 프로젝트와 상관없이 직접 지원

## 의사결정 기준

- 3단계까지 정확도가 목표에 못 미치면 → 카테고리를 줄이거나 정의를 고친 뒤 재평가
- 수집 중 7회 중 실패가 3회 이상 → 3단계 시작을 미루고 수집 안정화
- 공고 수가 라벨링 목표보다 적으면 → 키워드를 넓혀 수집을 2~3일 연장
