# 분류 체계 v1 (2026-10-20 확정)

공고를 직접 읽고 만든 기준입니다. 정답 세트(`data/labels.csv`) 라벨링과 3단계 자동 분류 평가는 모두 이 기준을 따릅니다.
기준을 바꾸면 버전을 올리고(v1 → v2) 바꾼 이유를 DECISIONS.md 에 적습니다.

## 라벨 1. IT 직무 여부
| 값 | 기준 |
|---|---|
| IT | 소프트웨어·시스템·데이터·네트워크 등 IT 기술 업무가 핵심인 직무 |
| 비IT | 마케팅, 영업, 재무, 교육, 경영지원 등. 제목에 AI 가 들어가도 업무가 IT 가 아니면 비IT |

## 라벨 2. 직무군 (IT 인 공고만)
주된 업무 하나만 고릅니다. 둘 이상 걸치면 제목이 가장 강조하는 쪽을 고릅니다.

| 직무군 | 기준 |
|---|---|
| 백엔드 | 서버, API, DB 개발 |
| 프론트엔드 | 웹 화면 개발 |
| 풀스택 | 프론트와 백엔드를 모두 명시 |
| 모바일 | 안드로이드, iOS 앱 개발 |
| AI·ML | AI 모델, LLM, 에이전트, NLP, 컴퓨터 비전 개발 |
| 데이터 | 데이터 분석, 데이터 엔지니어링, 데이터 모델링 |
| 임베디드·HW | 펌웨어, 임베디드 소프트웨어, 하드웨어 |
| 보안 | 보안 개발, 보안 점검·관제 |
| 인프라·QA | 서버 운영, 클라우드, DevOps, 테스트·품질 |
| 네트워크 | 네트워크 장비·망 구축 및 운영, 통신 |
| 기획·PM | 서비스 기획, 프로덕트 매니저 |
| 기타IT | 위 어디에도 맞지 않는 IT 직무 |

## 주의: 이름이 같아 헷갈리는 값
- 로켓펀치 업종 `IT_NETWORK` 는 "인터넷 서비스 회사"를 뜻합니다. 직무군 `네트워크`(네트워크 엔지니어 업무)와 무관합니다.
- 로켓펀치 직무 `job_category` 의 `dev` 는 거친 분류라 3단계에서 비교할 "기본 분류 기준선"으로만 씁니다.

## 신입 적합도
직접 라벨링하지 않고 API 의 `seniorities` 에 `BEGINNER` 가 있으면 신입 가능으로 봅니다.

## 보류한 것
- 의료 도메인 여부: 사용자가 의료 분야 지식이 없고 IT 중심으로 가기로 해서 제외. 필요해지면 v2 에 추가.
