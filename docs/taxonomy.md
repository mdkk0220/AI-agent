# 분류 정의서

**버전: v0 (가설)**. 수집 데이터를 직접 읽으면서 v1로 고칩니다. 기준을 바꾸면 버전을 올리고, 원본에서 다시 분류합니다.

입력은 **제목·키워드·직무명·업종명·회사명**뿐입니다 (본문 없음). 그래서 "제목만으로 판단이 안 되면 `기타`"가 정상적인 답입니다.

## 축 3. 의료 도메인 여부 (예/아니오)

의료 도메인(HIS, EMR, PACS, HL7/FHIR, 의료데이터, 의료기기 SW 등)과 **직접** 관련되면 `예`. 회사가 의료업종이어도 직무가 의료와 무관한 사내 시스템이면 `아니오`로 할지는 공고를 읽으며 정합니다 (경계 사례에 기록).

의료 키워드 사전 (전공 지식으로 계속 추가):

`HIS, EMR, EHR, PACS, OCS, HL7, FHIR, DICOM, 병원, 의료, 의료기기, 의무기록, 진료, 처방, 임상, 보건, 제약, 바이오, 헬스케어, 디지털 치료, 원무`

## 축 4. 경력 조건

사람인 `experience-level.code`를 그대로 사용합니다: 1 신입 / 3 신입·경력 / 0 경력무관 / 2 경력. 신입 지원 가능은 0·1·3.

## 축 5. 기술스택 (다중, 추출)

제목·키워드에 적힌 기술만 추출합니다 (본문 없음). 사전은 코드와 함께 관리합니다.

## 사람인 기본 분류와의 비교 (baseline)

사람인이 이미 주는 `job-mid-code`, `job-code`, `industry` 값을 **비교 기준**으로 둡니다. 정답 세트에서 `사람인 기본 분류 vs 내 규칙 vs LLM`을 비교해, 내 분류 축(의료 도메인 여부, 세부 직무)이 기본 분류보다 나은 점을 보여줍니다.

## 라벨링 규칙

1. 모델 예측을 보지 않고 라벨링한다.
2. 애매하면 `기타`로 두고 사례를 이 문서의 경계 사례에 적는다.
3. 50~100건 중 일부(20건 정도)는 며칠 뒤 다시 라벨링해서 내 일관성을 확인한다.
4. 가능하면 일부를 다른 사람(선배, 친구)이 따로 라벨링해 일치율을 본다.
5. 기준을 바꾸면 버전을 올리고, 기존 라벨은 바뀐 기준으로 다시 검토한다.
